# LLDP internals

How `nos-lldp` is built, moved from `lldp/CLAUDE.md` (#264) so the always-loaded file keeps only rules and pitfalls. The rules to respect when editing the crate are in [`lldp/CLAUDE.md`](../../lldp/CLAUDE.md).

## What is sent

`link::local_pdu`: Chassis ID (subtype 4, a MAC), Port ID (subtype 5, the interface name), TTL, Port Description (interface name), System Name (the config's `hostname`), System Description (`LldpSettings::effective_system_description`, default `nos`, no version: it would tell a neighbour which build to attack), System Capabilities, one Management Address per configured address, the org-specific TLVs below, End.

- **Org-specific TLVs** (type 127, `packet::OrgTlvs`, #63), all from `LinkConfig` except Link Aggregation:
    - 802.3 Maximum Frame Size (`00-12-0F`/4): `reconcile::max_frame_size`, effective MTU + 18. A bond member's MTU is its aggregate's (the bonding driver sets it); unset is 1500.
    - 802.1 VLAN Name (`00-80-C2`/3): one per `Dot1q(N)` member of the interface's switching profile, name = the broadcast domain cut to 32 bytes on a char boundary, by tag. An `Untagged` member has no VLAN id in this model (a bridge per domain, not a VLAN-aware one), so it gets none. `encode` stops adding them before the LLDPDU passes 1500 bytes (`debug!` per transmit).
    - 802.1 Link Aggregation (`00-80-C2`/7) on a `port_aggregate` member only: capable, and enabled with the bond's ifIndex iff `/sys/class/net/<if>/master/ifindex` reads (`link::read_aggregation`, per transmit). For a `Lacp` aggregate `nos-interfaced` enslaves only negotiated members, so "has a master" is "aggregated now" — no IPC to `nos-interfaced`/`nos-lacpd`. The port id is the aggregate's ifIndex (what lldpd sends); a membership change is advertised on the next transmit, not as `somethingChangedLocal` (`ponytail:` in `run`).
    - Not sent: Port VLAN ID (an `Untagged` member has no VLAN number to give) and 802.3 MAC/PHY (needs ethtool link settings and a MAU-type table). Both are decoded and shown.
    - Reconcile also subscribes to `SwitchingProfiles`/`PortAggregates`, since they feed these.

- **Capabilities**: *supported* is always Router|Bridge; *enabled* is Router, plus Bridge when the interface has a `switching_profile` (`LinkConfig.bridge`) — i.e. when it is actually a bridge port.
- **Management Address TLV**: address subtype 1/2 (IPv4/IPv6). If a kernel interface in the netns carries the address, the TLV uses interface numbering subtype 2 (ifIndex) with that interface's ifIndex. Otherwise it uses subtype 1 ("unknown", number 0).
    - The ifIndex comes from `nos_l2_socket::ifindex_of_address` (`getifaddrs`; the lowest ifindex if several interfaces carry it). It is resolved at every transmit (`local_pdu`'s `resolve` argument), not at reconcile, so an address `nos-interfaced` applies later is picked up without a link restart. It is a kernel fact: asking `nos-interfaced` would need a new IPC call and a config-name-to-device mapping.
    - The OID is empty (length 0). It would point at an SNMP MIB object, and nos runs no SNMP agent.
    - The shutdown LLDPDU carries none.
    - On receive, only subtype 2 keeps its number (`ManagementAddress.if_index`); subtype 1 or 3 decodes to `None`. `Display` renders `10.0.0.1 (ifindex 7)`, which is what `LldpNeighbor.management_addresses` and the `lldp neighbor learned` log carry.

- **Chassis MAC** is a locally-administered unicast MAC derived (FNV-1a) from the machine's hostname + machine-id (`reconcile::local_system_id`, copied from `nos-lacp`'s Actor System ID — same `ponytail:` caveat: two machines sharing both would collide and ignore each other as "our own frame"; upgrade path is a persisted random id file).
- **Destination** is the interface's configured group (default "nearest bridge" `01:80:C2:00:00:0E`). The socket joins that one group and the shared receive path drops any frame not addressed to it, so two ends on different groups never see each other — including each other's shutdown LLDPDU (the old group still gets it when one side reconfigures first). One group per interface; sending on several is not supported.

## Behavior worth knowing

- **Shutdown LLDPDU.** When a link with `transmit` stops for any reason (config change, interface removed, daemon shutdown), `link::run` sends a TTL-0 LLDPDU (`shutdown_pdu`, mandatory TLVs only) on the way out. Receivers drop the neighbor immediately instead of waiting out the 120s TTL. `nos-e2e lldp` depends on this.
- **Fast start** (802.1AB §9.2.5.19–21): a link opens with `TX_FAST_INIT` (4) frames at `MSG_FAST_TX` (1s) spacing before settling to `tx-interval`, and a *new* neighbor (`link::handle_rx` returns `true`) restarts that burst. Link start covers "something changed locally", since every local change restarts the link. Every periodic/fast frame spends a `txCredit` (max `TX_CREDIT_MAX` = 5, +1/s, refilled lazily in `refill_credit`); out of credit, the transmit retries in 1s — so a flapping neighbor can't force unbounded transmits. The shutdown LLDPDU is not credit-gated. Only a `New` neighbor triggers a burst — a refresh never does — so two systems settle rather than ping-ponging. The three constants are fixed (standard defaults), like `LINK_DOWN_RETRY`. `debug!` `lldp fast-start tx … remaining=<n>` marks each fast frame.
- **Neighbor identity** is (chassis id, port id), so one chassis heard on two ports is two neighbors. `NeighborTable` is capped at `MAX_NEIGHBORS_PER_LINK` (32) per interface: input is untrusted, and a hostile segment must not be able to grow the table without bound (802.1AB models the same limit as "too many neighbors"). Existing neighbors can still refresh when full. A refused newcomer is `Update::TableFull { first }`: counted (`too_many_neighbors` + `frames_discarded`), and `warn!`ed (`lldp neighbor table full, dropping new neighbor`) only when `first` — the first refusal since an entry last left — `debug!` after, so a hostile segment can't flood `nos-logd`. The standard's `tooManyNeighborsTimer` (also freezing the refused neighbors' info) is not implemented: dropping newcomers is already the safer bound.
- **Counters** (802.1AB §9.2.6, LLDP-MIB `lldpStatsTxPortTable`/`RxPortTable`): `link::Port.stats` (`nos_proto::LldpLinkStats`), bumped under the `SharedPorts` lock `handle_rx`/`send`/`expire` already take. `frames_out` counts only frames that actually left (`send` `Ok`); `frames_in` valid LLDPDUs except our own reflections; a decode error is `frames_in_errors` + `frames_discarded`; `packet::decode_counted` reports skipped optional TLVs — `tlvs_unrecognized` (types 9–126 and an org-specific TLV whose OUI/subtype nos doesn't decode), `tlvs_discarded` (a malformed/non-IP Management Address or one past the cap, a malformed/repeated known org TLV); `ageouts` is `NeighborTable::expire`'s count. Kept across link restarts (`run` resets only the neighbor table); `reconcile` drops a `Port` when the interface leaves the desired set, so `show lldp statistics` lists LLDP-enabled links only. No discontinuity timestamp.
- **Neighbor log limiting.** `link::LogBucket` (per link task, burst `LOG_CREDIT_MAX` = 5, one credit per `LOG_CREDIT_EVERY` = 10s, refilled lazily like `refill_credit`) gates the `info!` of `lldp neighbor learned` and the shutdown `lldp neighbor removed`; without a credit the same fields go to `debug!`. The table and counters are untouched. The `expired` removal needs a TTL to elapse, so it is not limited.
- **Ethertype check.** `nos_l2_socket`'s `recv`/`recv_frame` drop a frame whose bytes 12..14 are not the bound ethertype (`ethertype_matches`, skipped on the `ETH_P_ALL` STP sockets). The kernel can deliver a VLAN-tagged frame (0x8100 there) to an `AF_PACKET` socket bound to another ethertype; its payload offset would be wrong.
- **Tagged frames.** A frame that carried an 802.1Q tag is dropped by a kernel BPF filter (`L2Socket::open_untagged`), even when the NIC/veth offloaded the tag so the bytes read look untagged (#690).
- **Own frames are ignored twice**: `socket::payload_of_foreign_frame` drops frames whose source MAC is the port's own (an `AF_PACKET` socket also sees its own outgoing frames), and `link::handle_rx` drops any LLDPDU carrying our own chassis id (a looped cable or mirror port).
- **A down link is not fatal, and a down send is retried in 1s.** `ENETDOWN` on read/send is retried/skipped (`socket::is_link_down`); a periodic transmit that finds the link down is retried after `LINK_DOWN_RETRY` (1s) rather than waiting out the 30s interval — found by the e2e phase: `nos-interfaced` admin-ups a newly-configured interface on its own schedule, so the link task's first (immediate) transmit can lose that race; a task that ends on its own (socket can't open because the interface isn't in the netns yet, or a hard read error) is respawned by `reconcile` on its next resync.
- **Never leave an elapsed deadline armed** — the same rule as `nos-lacp/CLAUDE.md`. The expiry branch of `link::run`'s `select!` is guarded by `deadline.is_some()`, and handling it removes the entry the deadline belonged to.

## Modules

| Module | Role |
|--------|------|
| `main.rs` | Single-instance daemon args (`--watchdog-socket`, `--listen-socket`, `--log-socket` — the same shape as `lacp/src/main.rs`); resolves `nos-configd` via the broker, starts `server::start`, spawns `reconcile::run`. On shutdown signal every running link sends its shutdown LLDPDU before the process exits |
| `packet.rs` | Hand-rolled TLV encode/decode — pure, no I/O, round-trip and reject tests in-file. `decode_counted` also returns `TlvCounts` (discarded/unrecognized optional TLVs); `decode` drops them. `Lldpdu::chassis_display`/`port_display`/`enabled_capability_names` render the wire values for `show lldp neighbors` |
| `socket.rs` | A thin wrapper over the shared `nos-l2-socket` crate (`l2-socket/`, also used by `nos-lacp` — a leaf crate, so the star dependency graph holds): `open(interface, group)` fixes ethertype `0x88CC` and the receive buffer. The raw `AF_PACKET`/`unsafe` code lives there, not here |
| `neighbor.rs` | Pure `NeighborTable` — `apply` (`New`/`Refreshed`/`Removed`/`Ignored`/`TableFull { first }`), `expire`, `next_expiry`, `snapshot`. The caller passes `now` in, so aging is unit-tested without sleeping |
| `link.rs` | Per-interface task — `run()` owns the socket and drives it with `tokio::select!` over the next-transmit deadline (fast start, credit, `tx-interval`), the receive socket, and the next-expiry deadline. `handle_rx`/`expire`/`local_pdu`/`shutdown_pdu` are separately unit-tested. `SharedPorts` (`Arc<Mutex<HashMap<interface, Port { neighbors, stats }>>>`, one map and one lock for both) is what `server.rs` reads |
| `reconcile.rs` | Subscribes to `DiffScope::{Interfaces, Hostname}` purely as a resync trigger, always re-fetching the whole config, and keeps one link per interface with either flag set. A change to that interface's flags or to the hostname (System Name) restarts its link (`LinkConfig` equality); a finished task is respawned; a fixed 10s safety-net tick retries a link whose interface wasn't there yet. `desired_links` is the pure, unit-tested part |
| `server.rs` | Serves `nos_proto::lldp`'s `LldpRequest::GetNeighbors`/`GetStatistics` on `--listen-socket` (default `/run/nos/lldp.sock`, registered with the broker as `ServiceRef::Lldp`). Read-only, sorted by interface. Backs `nos-cli`'s `show lldp neighbors`/`statistics` and `GET /v1/lldp/{neighbors,statistics}` |
| (none) | `fetch_config`/`subscribe_diff` and `resolve_with_retry`/`resolve_once` come from `nos-daemon` |

## `nos-e2e lldp`

Real two-container verification (see [docs/e2e-phases.md](../docs/e2e-phases.md)). It reuses the `lacp` scenario's direct veth pairs (`World::link_veths`) between the two routers' network namespaces: a docker network is a Linux bridge, and a bridge never forwards `01:80:C2:00:00:0E` (it is in the reserved link-local group range), so no LLDPDU could ever cross one. It enables `lldp transmit` + `lldp receive` on both routers' `eth1` and confirms each `nos-lldpd` logs `lldp neighbor learned` with the other's System Name (`--hostname` in `nos-provision`, since both would otherwise advertise the default `nos`) and port id `eth1`, and that each finishes a fast-start burst (`remaining=0`) within 15s of that. It then turns transmit off on router-b and confirms router-a logs `lldp neighbor removed … reason="shutdown"` (tracing quotes a string field) **within 30s** — far under the 120s TTL, so passing proves the TTL-0 shutdown frame is handled, not that the entry aged out. The tuned-timers step (TTL 15) also has router-b advertise two management addresses: its eth0 address and `192.0.2.1`, which is on no interface. router-a must log `management_addresses=<IP_B> (ifindex N),192.0.2.1`, with N non-zero (docker keeps a veth's host-side index, so the value isn't fixed). That proves several TLVs per LLDPDU, a real ifIndex resolved in router-b's netns, and the "unknown" fallback. Removing `192.0.2.1` then restarts router-b's link, and router-a relearns it with only the first address. `--lldp-system-description e2e-edge` on router-a makes router-b log `system_description=e2e-edge` (the default, asserted earlier, is a bare `nos`). Then the org TLVs (`lldp_org_tlvs`, router-a sending): `mtu 9000` plus switching profile `sp1` trunking `eth1` into `bd1` at `dot1q 100` (`nos-provision --link-interface eth1`) makes router-b learn `capabilities=bridge,router max_frame_size=9018 vlans=100:bd1`; `eth2` enslaved into an `Xor` aggregate *before* LLDP transmit goes on there (so the first frame already has it) makes router-b learn `aggregation=enabled/<non-zero>` on `eth2`; then all of it is undone and router-b relearns `capabilities=router max_frame_size=1518`. `bd1`/`sp1` are `switching`'s own names on purpose: bridge ids are never freed, so a new domain would take the `br1` that phase expects. After that step it reads `GET /v1/lldp/statistics` on both routers (`eth1`: frames sent and received, no errors, no unrecognized TLVs), then `SIGSTOP`s router-b's `nos-lldpd` — no shutdown frame — and requires router-a to log `lldp neighbor removed … reason="expired"` within 25s with `ageouts` up by one, then `SIGCONT` and a relearn. Then transmit comes back and both sides learn each other again (router-b within 15s, well inside router-a's 30s interval, because a new neighbor triggers a fast-start burst). Dropping receive on router-a restarts its link transmit-only, and disabling everything stops the link.

tooManyNeighbors and the TLV counters stay unit-tested (`neighbor.rs`, `link.rs`, `packet.rs`): crafting 33 chassis or unknown TLVs on the wire would need a frame injector the image doesn't have. `show lldp neighbors`/`statistics` aren't exercised by the e2e phase (`nos-cli` has no scriptable one-shot mode, see root `CLAUDE.md`); the IPC round trips are covered by `lldp/tests/server.rs` (real socket) and `cli/tests/lldp_client.rs`.
