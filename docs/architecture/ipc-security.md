# IPC security

Contributor-facing; moved from the root `CLAUDE.md` (#260). Operator view: [docs/README.md](../README.md).


Every daemon-to-daemon and client-to-daemon connection is mutually authenticated TLS (`nos-pki`), with `nos-watchdogd` as the CA:

- **Identity.** Each certificate carries one URI SAN `nos://<role>/<name>` (`nos_proto::Role`: `watchdog`, `configd`, `logd`, `bgpd`, `ribd`, `ospfd`, `ospfv3d`, `interfaced`, `lacpd`, `lldpd`, `fdbd`, `restd`, `user`). A client dialing `ServiceRef::RibTable("rt1")` requires the server to prove it is `ribd/rt1` (`ServiceRef::role()`/`instance()`); a client that only has a socket path checks the role (`connect_role`).
- **Post-quantum only.** No classical fallback anywhere: the only key-exchange group is hybrid `X25519MLKEM768`, the only cipher `TLS13_AES_256_GCM_SHA384`, and IPC certificates are ML-DSA-65 (a verifier that accepts nothing else, so an ECDSA leaf fails even when it chains to a trusted CA). One policy, in `pki/src/policy.rs`, on the aws-lc-rs provider. The REST listener has the same key exchange but **ECDSA P-256** certificates from a second CA, so browsers and stock clients can still present one; a REST certificate never opens an IPC socket, nor an IPC one the REST API. `Policy::Syslog` (`nos-logd` dialing a syslog collector, RFC 5425, #71) is the same key exchange and TLS 1.3 with the classical signatures webpki supports, since no deployed collector holds an ML-DSA certificate. The one classical path is the per-collector `allow-tls12` opt-in: TLS 1.2 with ECDHE-AES-GCM suites, confined to `pki/src/syslog.rs` (every classical group wrapped to be TLS 1.2-only, so TLS 1.3 stays post-quantum) and unreachable from IPC and REST.
- **Handoff.** The watchdog creates two ephemeral in-memory CAs at start (writing only the public `ca.crt` and `rest-ca.crt` to `--pki-dir`, default `/run/nos/pki`) and, for **every spawn** in `supervisor::supervise_one`, mints a fresh keypair + leaf and writes it to the child's piped **stdin** — never argv, environment or disk. Daemons have no plaintext fallback. The watchdog's own identity rotates in-process.
- **Rotation.** Leaves are valid `--pki-leaf-lifetime` (24h) and re-pushed down the same stdin every `--pki-rotate-every` (8h); daemons swap them in hot (`Identity::update`) — new connections use the new certificate, established ones are untouched, so a long-lived stream (e.g. `nos-bgpd`→`nos-ribd`'s route push) outlives its handshake certificate and only a *reconnect* needs the rotated one.
- **Revocation.** The IPC CA keeps an RFC 5280 CRL, pushed down every child's stdin with its identity and enforced on every new handshake (never on an open connection): a child's certificates are revoked when its process exits, a user's IPC certificates when the user is deleted or its password changes. No CA roll: a child can't outlive the watchdog. See `pki/CLAUDE.md`.
- **Login.** The broker socket is TLS with the client certificate **optional**. An unauthenticated peer may send only `WatchdogRequest::Login { user, password, csr_der }`: the watchdog reads the users from `nos-configd` (its own identity), verifies with `nos_password::verify_or_dummy` (1s delay per failure, dropped after 3), and returns a `user/<name>` certificate for the **public key in the CSR** (the subject/SANs the CSR asks for are discarded). `RenewCert` trades a still-valid user certificate for a fresh one without a password, refused once the user is deleted; `nos` renews at half-life (`--pki-user-lifetime`, 8h). `ResolveEndpoint` requires a certificate. `nos-restd` uses the same broker for its REST clients (`RestLogin`/`RestRenew`, REST-CA certificates, no per-connection throttle — `nos-restd` allows one guess per second per username itself) and for its listener certificate (`IssueRestServerCert`).
- **Socket mode.** Every IPC socket is `0600`, owned by the daemon's uid (chmod right after bind, in `nos-pki`; the process umask is not relied on). All NOS processes run as `nos`, so same-uid clients connect.
- **Authorization.** Each server has a pure, unit-tested `allowed(role, &request)` with **no wildcard arm** (a new request variant won't compile until classified); a refused request is logged with role+name and the connection is closed. Config *reads* are open to every authenticated daemon; edits/saves are `user`/`restd` only (`config/src/authz.rs`); the broker's `allowed` (`watchdog/src/broker.rs`) likewise: `Login` anyone, `ResolveEndpoint` any certificate, `RenewCert` `user`, the three `Rest*` requests `restd`; route pushes are each daemon family's alone (`ribd`: `bgpd` → `PushBgpRoutes` and the `BgpRouteCount` query (graceful restart), `ospfd`/`ospfv3d` → `PushOspfRoutes`; the redistribution feeds `RedistributeRoutes` into `nos-ospfd`/`nos-ospfv3d` are `ribd`'s); `PushLacpMembers` is `lacpd`'s, `PushBfdMembers` `bfdd`'s, `SubscribeLinks` `ospfd`/`ospfv3d`'s; `PushEvpnRoutes` (to `nos-fdbd` and to `nos-ribd` alike) is `bgpd`'s, `RedistributeMacs` is `fdbd`'s and `RedistributeEvpnPrefixes` is `ribd`'s; `nos-ribd` answers `GetEvpnIrb` (symmetric IRB) to `fdbd` only; queries are `user`/`restd`, except that `nos-interfaced`'s status queries are also open to the daemons that resolve addresses through it (`bgpd`, `ribd` — for its connected routes — `ospfd`, `ospfv3d`, `fdbd`); `nos-logd` accepts pushes from any daemon and reads from `user`/`restd`; `ribd`'s `GetVrfName` is also open to `logd` (a syslog collector's VRF). Role-level only — see `pki/CLAUDE.md`'s ceilings.
- **`nos-configd --listen` is Unix-only**: the TCP variant was removed, since a network listener would bypass all of this.

- **Key hygiene.** Every NOS-owned buffer holding a private key is `nos_pki::Zeroizing<Vec<u8>>` (wiped on drop): `Bundle.key`, the `Bundle::encode()` frame and the `read_from` body, and the key `generate_csr`/`generate_csr_for` return (the `nos` session key, `nos-restd`'s listener key). Use the `nos_pki::Zeroizing` re-export; no crate adds `zeroize` itself.
  - Ceilings: rustls/aws-lc-rs keep their own copy of the loaded key; rcgen's `KeyPair` and the REST test client's owned `PrivatePkcs8KeyDer` are not wiped; tokio stdin buffers, the kernel pipe buffer, swap and core dumps are out of reach.
