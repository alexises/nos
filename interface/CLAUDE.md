# nos-interface — Interface Reconciliation Daemon

Reconciles configured network interfaces against the OS (binary `nos-interfaced`, a single process for every interface — unlike `nos-ribd`, `nos-watchdog` spawns exactly one instance regardless of how many `Interface` sections exist in config).

## Scope

Applies configured interface state (addresses, admin-up, VRF enslavement) to the OS through a swappable **driver** (`driver::InterfaceDriver`), selected via `--driver` (default `linux` on Linux, `noop` elsewhere/for tests):
- `driver::noop::NoopInterfaceDriver` — logs the state that would be applied; no OS effect. Today's original placeholder behavior, kept as the portable default.
- `driver::linux::LinuxInterfaceDriver` — the real implementation, via the `rtnetlink` crate. Only ever *configures* an ordinary interface already present in the netns (see "Why one process for all interfaces" below) — it never creates one. The two deliberate, narrow exceptions are a **loopback interface** and **broadcast-domain bridges/802.1q sub-interfaces**, both described below. Diffs live kernel state (addresses, current master) against desired state on every call rather than trusting any cached record of what it applied last, which makes it self-healing against out-of-band kernel drift. Address reconciliation never touches a kernel-reported address at scope `Link` (e.g. IPv6 link-local) — NOS only owns addresses it put there itself. `Interface.addresses`' per-address `label` (`nos_proto::InterfaceAddress`) is stored but not yet applied to the kernel (no `ip addr ... label` call) — future work. Requires `NET_ADMIN`/`NET_RAW`; see the `Dockerfile`/`docker-compose.yml`.

  A loopback interface: an `Interface` whose config `name` starts with `loopback-` (`nos_proto::LOOPBACK_PREFIX`/`loopback_table_name` — the routing table it's for is the rest of the name, e.g. `loopback-rt1` is for table `rt1`; there is no separate "kind" field). For that one case, the driver creates (and later deletes) a `dummy` kernel device named `lo<table_id>` — never the interface's own config name, mirroring how `nos-ribd`'s VRF kernel name (`vrf<table_id>`) is independent of `RoutingTable.name` — since Linux only ever has one real `lo` per network namespace.

  **L2 switching (bridges/802.1q) and L3 routed subinterfaces, unified per tag.** `Interface.switching_profile` names a `SwitchingProfile` (a trunk-style list of `(broadcast_domain, tag)` memberships — see `nos_proto::schema::switching_profile`) — L2 config, unchanged, still a physical-interface-level field. `Interface.subinterfaces: Vec<Subinterface>` is L3 config instead: `tag == 0` is the untagged/native case, applied directly to the physical (or loopback) link exactly like the old flat `Interface.addresses`/`routing_table` fields it replaced; `tag` in `1..=4094` is a real 802.1q VLAN, realized the same way a `Dot1q` switching-profile member is — its own `<interface>.<tag>` kernel sub-interface. Because a `BroadcastDomain` is one L2 domain but two different interfaces can tag it with two *different* local dot1q values (the tag is locally significant per interface, not a global property of the domain), the driver creates **one Linux bridge device per configured `BroadcastDomain`** — never a single shared 802.1Q-aware bridge with one global VID→domain mapping.

  **The domain's own SVI.** `BroadcastDomain.addresses`/`routing_table` (same flat shape as a loopback `Interface`'s L3 config — a domain's bridge has no VLAN/tag concept of its own) make the bridge device itself an SVI (switch virtual interface), a routed L3 attachment point for the domain as a whole. `ensure_broadcast_domain` reconciles these directly onto the bridge with the identical `reconcile_addresses`/`reconcile_master` calls `apply` already makes for a physical/loopback link — a `BroadcastDomainState` (mirroring `nos_proto::BroadcastDomain`) carries them from `state::build_from_config` alongside the domain's name. The bridge and whatever interfaces are enslaved into it as L2 members are separate Linux links, so there is no conflict between a domain's own VRF assignment and any member's.

  `LinuxInterfaceDriver::apply` reconciles all of this per interface in one pass: the physical (or loopback) link itself gets `subinterfaces`' tag-0 addresses and is enslaved into either the resolved VRF (from that tag-0 subinterface's `routing_table`) or the resolved bridge (from an `Untagged` switching-profile member) — at most one of the two, since commit-time validation (`valid_subinterface_and_switching_profile_tags`) guarantees tag 0 is never claimed by both. Every tag>0 sub-link — whether an L2 `Dot1q` switching-profile member or an L3 `tag>0` `Subinterface` — is reconciled by one shared function, `reconcile_tagged_subinterfaces`, over the *union* of both kinds' tags (never scanned separately, or one kind's live sub-link would be mistaken for the other's stale one and deleted): it creates/deletes each `<interface>.<tag>` VLAN sub-interface as needed, then enslaves it per a `TaggedMaster::{Bridge(domain), Vrf{routing_table, addresses}}` — `Bridge` enslaves into that domain's bridge (no addresses, as before); `Vrf` enslaves into the resolved routing table's VRF (or leaves the sub-link masterless if `routing_table` is unset) and applies that `Subinterface`'s own addresses, so two interfaces can use different tags for the same L2 domain and still land on the same bridge, while an L3 sub-interface gets its own independent addressing/VRF regardless of what other tags on the same physical interface are doing. Bridge naming mirrors the loopback/VRF pattern: `br<id>`, where `<id>` is allocated on first use and persisted to this driver's own private registry (`driver::bridge_registry`, `--bridge-registry-path`, default `/var/lib/nos/linux-driver/bridge-ids.yaml` — same directory `nos-ribd`'s `table-ids.yaml` lives in, since every daemon here runs inside one watchdog container). Bridges are created/removed eagerly from every configured `BroadcastDomain`, independent of whether any interface currently references one — same pattern as `nos-ribd`'s VRF-per-`RoutingTable` — and are reconciled *before* any interface's own `apply` in the same resync, since enslavement resolves each bridge by name.

**Cross-daemon IPC to `nos-ribd`.** When an interface's `routing_table` is set (or, for a loopback interface, is implied by its name), `LinuxInterfaceDriver` needs the real Linux interface name of that table's VRF device — but VRF creation and table-id allocation are owned entirely by the *owning* `nos-ribd` instance's own driver (see `rib/CLAUDE.md`), not derivable independently. So the driver resolves that table's `nos-ribd` socket via the watchdog broker (`ServiceRef::RibTable(name)`) and asks it directly over IPC (`RibRequest::GetVrfName` → `RibEvent::VrfName(Option<String>)`, see `driver::rib_client`) — the first direct daemon-to-daemon link in this codebase (see root `CLAUDE.md`). A loopback interface additionally asks the same instance for its raw numeric table id (`RibRequest::GetTableId` → `RibEvent::TableId(Option<u32>)`, symmetric to `GetVrfName`) to compute its kernel device name. "Not resolvable yet" (broker doesn't know that table, connect failure, or rib hasn't created a VRF/table id yet) is a normal, expected, frequently-recurring condition, never an error — it's silently retried by the periodic re-apply tick (`reconcile::REAPPLY_INTERVAL`), not just on the next config diff, since the other daemon's readiness isn't itself a config change.

There is an external query API: `server.rs` serves `nos_proto::interface::{InterfaceRequest, InterfaceEvent}` for `nos-cli`'s `show interface` command (see root `CLAUDE.md`'s "Endpoint broker" section for how a client finds this instance's socket — `ServiceRef::Interfaces`, resolved directly by the watchdog like `ServiceRef::Config`, since there's exactly one instance). A query reflects *desired* state (from the running config) — with the `linux` driver running, that's normally also what the kernel has, but the two can transiently diverge (e.g. right after a config change, or if the VRF isn't up yet).

`InterfaceRequest::GetBroadcastDomain { name }` → `InterfaceEvent::BroadcastDomain(BroadcastDomainStatus)`/`NotFound` is the same query shape for a `BroadcastDomain`'s own SVI (`state::Interfaces.by_domain`, populated in `build_from_config`'s existing broadcast-domain loop, mirroring `by_name`). Added for `nos-ospfd` to resolve a `BroadcastDomain.ospf_profile` attach point's local address the same way `resolve_local_address` already asks this daemon for a `Subinterface`'s — this is the second direct daemon-to-daemon IPC link that isn't `GetVrfName` (see root `CLAUDE.md`'s "Linux drivers"), and, like that one, exists because the answer isn't derivable from `nos-ospfd`'s own already-fetched `Config` alone (asking the owning daemon stays consistent even though today's answer happens to just mirror desired config, in case a future kernel-derived address ever isn't). `BroadcastDomainStatus.bridge_name: Option<String>` (`None` until the driver has actually allocated/created the bridge) carries the domain's real Linux bridge device name in the same reply — `InterfaceDriver::ensure_broadcast_domain` now returns it (`Ok(ifname)` on the `linux` driver, a synthesized `noop-br-<name>` placeholder on the `noop` one) rather than `Ok(())`, and `build_from_config` stores it onto the `BroadcastDomainState` it's already building. `nos-ospfd` needs this to bind its own raw OSPF socket to the domain's bridge (its SVI) rather than the shared VRF device — see `ospf/CLAUDE.md`'s `socket.rs` entry for why VRF-wide binding is wrong for a protocol with no port/connection concept to demultiplex by.

## Why one process for all interfaces, unlike nos-ribd

`RoutingTable`/`BgpInstance` each get an isolated in-memory computation (a RIB, a BGP session) that benefits from process isolation and independent restart. An interface is not an isolated resource — every `nos-interfaced` instance would ultimately be reaching into the same OS network namespace — so there's no isolation benefit to one process per interface, and per-interface spawn/teardown would only add churn on every config edit. See root `CLAUDE.md`'s "Process supervision" section for how `nos-watchdog` supervises this as a single fixed process, the same way it supervises `nos-configd`.

## Modules

| Module | Role |
|--------|------|
| `main.rs` | Arg parsing (`--watchdog-socket`, `--listen-socket` default `/run/nos/interface.sock`, `--driver` default platform-dependent, `--bridge-registry-path`), resolves `nos-configd`'s address via the watchdog broker before starting, constructs the selected `InterfaceDriver`, SIGINT+SIGTERM shutdown wait, spawns `reconcile::run` and `server::start` sharing one `Arc<RwLock<Interfaces>>` |
| `state.rs` | `InterfaceState` (carrying `switching_profile`/`switching_profile_members`, the latter resolved from config — pure local lookup, no IPC needed — plus `subinterfaces: Vec<SubinterfaceState>`, the wire twin of `nos_proto::Subinterface`; `addresses`/`routing_table` on `InterfaceState` itself are populated only for a loopback interface, empty otherwise), `BroadcastDomainState` (the wire twin of `nos_proto::BroadcastDomain` — name plus its own SVI `addresses`/`routing_table`, plus `bridge_name: Option<String>`, filled in from the driver's own return value, not desired config), `Interfaces` (name-keyed `by_name` and `by_domain` collections, mirroring `nos-rib`'s `Rib`, plus the last-resync's configured `BroadcastDomain` names purely for diffing removals — `get`/`get_domain` back `server.rs`'s two query kinds), `build_from_config` (async — calls `driver.ensure_broadcast_domain`/`remove_broadcast_domain` per configured/removed domain, storing the returned bridge name and populating `by_domain` in the same pass, then `driver.apply` per interface and `driver.remove` for any interface dropped from config since the previous resync) |
| `driver/mod.rs` | `InterfaceDriver` trait (`apply`, `remove`, `ensure_broadcast_domain` — returns the bridge's real kernel device name, `Result<String, DriverError>`, not just `Result<(), DriverError>` — `remove_broadcast_domain`), `DriverError` |
| `driver/noop.rs` | `NoopInterfaceDriver` |
| `driver/linux.rs` | `LinuxInterfaceDriver` — real `rtnetlink` implementation, including `reconcile_tagged_subinterfaces`/`TaggedMaster` (see above) |
| `driver/bridge_registry.rs` | This driver's own private persisted state (`--bridge-registry-path`, default `/var/lib/nos/linux-driver/bridge-ids.yaml`): allocates a bridge id (1, 2, 3, ... — just a short unique device-name suffix, never a real kernel table id, so no reserved range) for a `BroadcastDomain` name on first use and remembers it across restarts, mirroring `nos-ribd`'s `table_registry` exactly. **No other process ever reads this file.** |
| `driver/rib_client.rs` | One-shot `get_vrf_name`/`get_table_id` — the client side of the cross-daemon `RibRequest::GetVrfName`/`GetTableId` IPC |
| `config_client.rs` | Own `fetch_config` (`Request::Get`) / `subscribe_diff` (`Request::SubscribeDiff`) — reimplemented rather than shared with `nos-cli`/`nos-watchdog`/`nos-rib`, per the root `CLAUDE.md`'s star dependency graph |
| `watchdog_client.rs` | `resolve_with_retry` — resolves `nos-configd`'s address via the watchdog broker, retrying indefinitely (fixed 1s delay) until it succeeds or shutdown fires; `resolve_once` — a non-retrying sibling used by `LinuxInterfaceDriver` to resolve a routing table's `nos-ribd` instance on every reconcile pass, where "not available" must return quickly rather than block |
| `reconcile.rs` | Steady-state loop: subscribes to `Interfaces`/`BroadcastDomains`/`SwitchingProfiles` diffs purely as a resync trigger, always re-fetching the whole config and rebuilding `Interfaces` from scratch rather than applying diffs incrementally (diffs carry only display strings, not structured data); also re-applies on a fixed `REAPPLY_INTERVAL` (10s) even without a new diff, since VRF/bridge readiness is an external condition no config diff signals; writes the rebuilt `Interfaces` through the shared `Arc<RwLock<Interfaces>>` |
| `server.rs` | Binds `--listen-socket` and serves `InterfaceRequest::GetInterfaces`/`GetInterface`/`GetBroadcastDomain` from the shared `Arc<RwLock<Interfaces>>`, read-locked per request |
