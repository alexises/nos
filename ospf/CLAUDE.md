# nos-ospf — OSPF Component

OSPF daemon for NOS (binary `nos-ospfd`, one process per `OspfInstance`, dynamically spawned by `nos-watchdog` — see root `CLAUDE.md`'s "Process supervision" section).

## Scope

`nos-ospfd` resolves its own configured instance/areas/profiles from `nos-configd`, and runs a real RFC 2328 Hello protocol on every `Subinterface.ospf_profile` (point-to-point) and `BroadcastDomain.ospf_profile` (multi-access, with RFC 2328 §9.4 DR/BDR election) attach point — a real raw protocol-89 socket, VRF-scoped, joined to the AllSPFRouters (224.0.0.5) multicast group. Adjacency formation stays deliberately shallow, matching how `nos-bgp` originally shipped OPEN/KEEPALIVE-only before route exchange landed later:

- **Neighbor FSM depth**: `Down` → `Init` → `TwoWay` only (`ospf::neighbor::NeighborState`), on both network types. No DBD/LSR/LSU/LSAck, no LSDB, no `ExStart`/`Exchange`/`Loading`/`Full` — those need real LSAs to synchronize, which don't exist yet. `TwoWay` (both sides list each other in their Hellos) is this phase's "established" milestone for a neighbor; DR/BDR election on a broadcast link runs independently of that ceiling (RFC 2328 only progresses DR/BDR-adjacent neighbors past `TwoWay` anyway, and nothing here ever does regardless of DR/BDR-ness).
- **Network type**: `Subinterface.ospf_profile` attach points (a VLAN sub-interface modeling one link to one peer) run point-to-point — at most one neighbor, no election, `link::InterfaceState` fixed at `PointToPoint`. `BroadcastDomain.ospf_profile` (multi-access SVI) attach points run broadcast — potentially many neighbors keyed by router-id, a `Waiting` interface state on start (wait-timer = dead-interval), then a real DR/BDR election (`ospf::election::elect`) settling into `Dr`/`Backup`/`DrOther`. A loopback (`Interface.ospf_profile`) attach point still has no peer to Hello with and stays **log-only**, resolved purely from the already-fetched `Config` (`reconcile::attach_points_for`). Both real network types Hello via multicast 224.0.0.5, not unicast — RFC 2328 has no unicast Hello.
- `OspfProfile.network_type: Option<NetworkType>` overrides the type an attach point gets when set; left `None`, it defaults per attach-point kind (`Subinterface` → `PointToPoint`, `BroadcastDomain` → `Broadcast`) — resolved in `reconcile.rs`, not the schema, since one profile can be referenced by attach points of different kinds at once. Never validated against the attach point's actual kind (real OSPF allows forcing either behavior on either kind of link).

`OspfProfile` carries `hello_interval`/`dead_interval`/`priority: Option<u16|u8>` (`None` defaults to `HELLO_INTERVAL_DEFAULT`/`DEAD_INTERVAL_DEFAULT`/`PRIORITY_DEFAULT` — 10s/40s/1, RFC 2328 Appendix C.3), `hello_interval`/`dead_interval` validated (`dead_interval` must exceed `hello_interval` when both are set) the same way `BgpPeerGroup.hold_time`/`keepalive_interval` are, one level up on `OspfArea.profiles` (`ospf_profile::valid_profile_timers`). `priority` governs DR/BDR election eligibility on a `Broadcast` link (`0` means "never eligible") and is sent on the wire (functionally inert) on a `PointToPoint` one too. `cost: Option<u16>` (range `1..=65535`) is stored/validated/rendered only — this NOS has no SPF/LSDB yet, so it has no behavioral consumer, a forward-declared placeholder for a future SPF phase. All five fields are `nos-cli`-editable (`set hello-interval|dead-interval|cost|priority|network-type ...` while navigated into an `OspfProfile`, or the fully-qualified form from anywhere — mirrors `BgpPeerGroup.hold_time`'s exact CLI precedent).

## Modules

| Module | Role |
|--------|------|
| `main.rs` | Arg parsing (`--instance`, `--watchdog-socket`, `--listen-socket`, `--log-socket`), resolves `nos-configd`'s address via the watchdog broker before starting, SIGINT+SIGTERM shutdown wait, spawns `reconcile::run` and `server::start` sharing one `Arc<link::LinkManager>` |
| `config_client.rs` | Own `fetch_config` (`Request::Get`) / `subscribe_diff` (`Request::SubscribeDiff`) — reimplemented rather than shared with the other component crates, per the root `CLAUDE.md`'s star dependency graph |
| `watchdog_client.rs` | `resolve_with_retry` (used once at startup for `ServiceRef::Config`) and `resolve_once` (used every resync for `ServiceRef::RibTable`/`ServiceRef::Interfaces`, where "not available" must return quickly rather than block) |
| `rib_client.rs` | One-shot `get_vrf_name` — the client side of `RibRequest::GetVrfName`, reimplemented from `nos-bgp`'s own copy per the star dependency rule |
| `interface_client.rs` | One-shot `get_interface`/`get_broadcast_domain` — the client side of `InterfaceRequest::GetInterface`/`GetBroadcastDomain`, likewise reimplemented from `nos-bgp`'s own `get_interface` (the broadcast-domain query is new to `nos-interfaced` itself — see `interface/CLAUDE.md`) |
| `packet.rs` | RFC 2328 Appendix A.3.1/A.3.2 Hello packet wire format (`encode_hello`/`decode_hello`) — pure, no I/O. Checksum is the standard RFC 1071 ones-complement-of-ones-complement-sum (same as IP/TCP/ICMP), **not** OSPFv3's Fletcher checksum or the LSA checksum (RFC 905 Annex B) — neither applies since this phase has no LSAs. `router_priority`/`designated_router`/`backup_designated_router` are real fields (used by broadcast-link election; sent but functionally inert on point-to-point); network mask stays always-zero/ignored on both (RFC 2328 §10.5 exempts point-to-point, and this NOS never implements the address-mask subnet check broadcast links would otherwise want) |
| `neighbor.rs` | `step(NeighborState, Event) -> NeighborState` — the pure RFC 2328 §10.5 neighbor transition table, restricted to `Down`/`Init`/`TwoWay`, unit-tested directly with no I/O. Applied once per neighbor — unchanged by network type, `link.rs` just calls it once (point-to-point) or per-neighbor-in-a-map (broadcast) |
| `election.rs` | `elect(Candidate, &[Candidate]) -> ElectionResult` — the pure RFC 2328 §9.4 DR/BDR election algorithm (priority/router-id tie-break, incumbent-DR stickiness, priority-0 exclusion), unit-tested directly with no I/O. `link.rs` re-runs it after every Hello-driven neighbor-state change and dead-sweep once a broadcast link is out of `Waiting` — a `ponytail:`-flagged single-pass simplification of RFC 2328's "recompute twice if self's own role changed" refinement |
| `socket.rs` | `OspfSocket` — a raw protocol-89 socket, VRF-scoped via `socket2::Socket::bind_device` (`SO_BINDTODEVICE`, the same mechanism `bgp/src/tcp.rs` uses for TCP), joined to 224.0.0.5 on the link's own local address (`join_multicast_v4`). `recv_hello` strips the IP header raw sockets always deliver on receive (even without `IP_HDRINCL`) using the IHL nibble |
| `link.rs` | `LinkConfig` (gains `network_type`/`priority`, part of the wholesale-diffed struct) / `LinkStatus` (an `InterfaceState` — `PointToPoint`/`Waiting`/`Dr`/`Backup`/`DrOther` — plus a `HashMap<Ipv4Addr, NeighborInfo>`, at most one entry on point-to-point) / `run` — one link's Hello send ticker, dead-interval tracking (a single `sleep_until` on point-to-point; a `ponytail:`-flagged 1s periodic sweep on broadcast, not N precise per-neighbor timers), and (broadcast only) the `Waiting`-state wait-timer plus election triggering. `LinkManager`, the OSPF analogue of `bgp::session::SessionManager` (much smaller: no shared listener, no auth, no collision resolution). `LinkManager::reconcile` diffs desired links by attach-point (restart on any resolved-field change, exactly like `bgp::session::diff_peers`) and treats a link whose driver task ended on its own (e.g. socket-open failure) as "not currently running" so the next resync/re-apply tick respawns it. `neighbor_summaries` emits exactly one row per point-to-point link (even with no neighbor yet) and one row per currently-known neighbor on a broadcast link (zero if none yet) |
| `reconcile.rs` | Steady-state loop: subscribes to `OspfInstances` diffs purely as a resync trigger, always re-fetching the whole config, plus a fixed 10s re-apply tick (same justification as `nos-bgp`'s own `REAPPLY_INTERVAL` — VRF/interface readiness is an external condition no config diff signals). Logs this instance's `router_id`/`routing_table`/areas/profiles, each profile's `cost` (observability only, no behavioral use), and each profile's attached interfaces (`attach_points_for`, unchanged); resolves each `Subinterface.ospf_profile` attach point's VRF/local address (`resolve_vrf`/`resolve_local_address`, mirroring `nos-bgp`'s `resolve_source_address`) and each `BroadcastDomain.ospf_profile` attach point's VRF/local address (`resolve_vrf`/`resolve_broadcast_domain_local_address`, the latter asking `nos-interfaced`'s new `GetBroadcastDomain` query rather than reading `Config.broadcast_domains[].addresses` directly, for the same "ask the owning daemon" reasoning `resolve_local_address` already follows), and hands the resulting `LinkConfig`s to `LinkManager::reconcile` |
| `server.rs` | Binds `--listen-socket` and serves `OspfRequest::GetNeighbors` from `LinkManager::neighbor_summaries` (backs `nos-cli`'s `show ospf neigh`) — resolved via the watchdog broker's `ServiceRef::OspfInstance`, the same pattern `nos-bgpd`/`nos-ribd`/`nos-interfaced`'s query listeners use |

## Watchdog/broker wiring

`nos-watchdogd` gives every `nos-ospfd` instance a real `--listen-socket` (`/run/nos/ospf-<name>.sock`) and registers it in `EndpointRegistry` under `EndpointKind::OspfInstance` — the `ServiceRef`/registry plumbing that already existed generically (see root `CLAUDE.md`'s "Endpoint broker") is now actually wired up, not just present.
